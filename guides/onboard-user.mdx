ByCard requires every end user to pass identity verification (KYC) before a card can be issued. You initiate this process by submitting the user's personal details and identity documents to the KYC endpoint. If the review fails, you can resubmit corrected data using the same API call.

## Prerequisites

Before you begin, make sure you have the following ready:

- An approved ByCard institution account and valid [API credentials](/started/authentication)
- The user's identity documents as base64-encoded images (front, back for ID cards, and a手持 photo)
- A unique user identifier (`acct_no`) that your system assigns to the user

## Steps

<Steps>
  <Step title="Collect user details and documents">
    Gather the user's full name, date of birth, nationality, address, contact information, and identity document. Encode the required document photos as base64 strings. Supported document types are `passport`, `idcard`, and `driver`.
  </Step>
  <Step title="Submit the KYC application">
    Send a `POST` request to `/api/v1/customers/accounts` with the user's data. The key required fields are:

    | Field | Description |
    | --- | --- |
    | `acct_no` | Your unique user ID (max 64 chars) |
    | `acct_name` | Your username for this user (max 64 chars) |
    | `first_name` | User's given name (max 50 chars) |
    | `last_name` | User's family name (max 50 chars) |
    | `birthday` | Date of birth in `YYYY-MM-DD` format |
    | `country` | ISO 3166-1 alpha-2 country code (e.g., `HK`) |
    | `nationality` | ISO 3166-1 alpha-2 nationality code |
    | `doc_no` | Identity document number (max 128 chars) |
    | `doc_type` | `passport`, `idcard`, or `driver` |
    | `front_doc` | Base64-encoded front photo (required unless a `token` is used) |
    | `back_doc` | Base64-encoded back photo (required when `doc_type` is `idcard`) |
    | `mix_doc` | Base64-encoded手持 photo (required unless a `token` is used) |
    | `country_code` | Phone country code, e.g. `+852` |
    | `mobile` | Phone number (max 32 chars) |
    | `mail` | Email address (163.com domains are not supported) |
    | `address` | Mailing address (max 256 chars) |
    | `zipcode` | Postal code (max 20 chars) |
    | `card_type_id` or `bank_id` | The card product or bank to associate with the user |

    <Note>
      When `doc_type` is `idcard`, `back_doc` is required. If you are using a third-party KYC provider token (e.g., SUMSUB, JUMIO), `front_doc` and `mix_doc` may be omitted.
    </Note>
  </Step>
  <Step title="Await the KYC webhook">
    After submission, ByCard reviews the application. You will receive a [KYC webhook](/api/webhook/kyc_events) with the `kyc-status` action when the review completes. A successful review allows you to proceed to card issuance.
  </Step>
  <Step title="Resubmit if the review fails">
    If the KYC review fails, correct the invalid fields and call the same endpoint again using the same `acct_no`. There is no separate resubmission API. Update any missing or incorrect documents, names, or addresses and retry.
  </Step>
</Steps>
