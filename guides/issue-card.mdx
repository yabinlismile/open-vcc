---
title: "Apply For and Activate a Card"
sidebarTitle: "Issue Card"
description: "Issue a ByCard debit or credit card to a KYC verified user, then activate it. Covers both virtual and physical card flows."
---

Once a user has passed KYC, you can issue a ByCard debit or credit card on their behalf. The application step creates the card record and returns a `card_no`, which you use for all subsequent card operations. Depending on the card type, you may need to activate the card before it can be used for transactions.

## Steps

<Steps>
  <Step title="Confirm the user passed KYC">
    Before you apply for a card, verify that the user's KYC status is approved. You can confirm this through the [KYC status query API](/api/kyc/user_accounts_status_query) or by receiving the [KYC webhook](/api/webhook/kyc_events).
  </Step>
  <Step title="Submit the card application">
    Send a `POST` request to `/api/v1/debit-cards` with the following required fields:

    | Field | Description |
    | --- | --- |
    | `acct_no` | Your unique user ID (same value used during KYC) |
    | `card_type_id` | The card product ID you want to issue |

    Optional fields include `address`, `country`, `state`, `city`, `zipcode`, `country_code`, `mobile`, `cust_tx_id`, and `card_number` (for bind-card products).

    <CodeGroup>

    ```json Request
    {
      "acct_no": "tevau_uat_008",
      "card_type_id": "63000001",
      "card_number": "",
      "urn": "",
      "address": "street 1",
      "country": "HK",
      "state": "moon",
      "city": "moon",
      "zipcode": "123456",
      "country_code": "",
      "mobile": "",
      "cust_tx_id": "ea7d3876a297432bb1f2f712060a1cff"
    }
    ```

    ```json Response
    {
      "code": 0,
      "msg": "SUCCESS",
      "result": {
        "card_no": "2665212122863000001****",
        "card_number": "430021****1144",
        "status": 2
      }
    }
    ```

    </CodeGroup>

    The response returns:

    - `card_no`: The internal card ID used for all future API calls (masks the real card number)
    - `card_number`: The real card number, masked for security (first 6 and last 4 digits only)
    - `status`: The initial card status (see [card status reference](/api/reference/enum_card_status))

    <Tip>
      Store the `card_no` securely in your database. You will need it for activations, funding, and management operations.
    </Tip>
  </Step>
  <Step title="Activate the card">
    Activation behavior depends on the card type.

    **Virtual cards** can be activated immediately by calling the activation endpoint.

    **Physical cards** must first reach the `activated` state. You typically wait for the [card activate webhook](/api/webhook/card_activate_events), then call the activation endpoint if required.

    Send a `POST` request to `/api/v1/debit-cards/status` to activate the card:

    | Field | Description |
    | --- | --- |
    | `card_no` | The card ID returned from the application step |
    | `acct_no` | Your unique user ID |
    | `cvv` | Required for certain physical card products |

    <CodeGroup>

    ```json Request
    {
      "acct_no": "tevau_uat_008",
      "card_no": "436039672000001****"
    }
    ```

    ```json Response
    {
      "code": 0,
      "msg": "string",
      "result": {
        "card_type_id": "72000001",
        "card_no": "4360396720000016920",
        "acct_no": "tevau_uat_008",
        "status": 1
      }
    }
    ```

    </CodeGroup>

    After successful activation, virtual cards expose the full card number, CVV, and expiration date through the bank interface or [sensitive data query API](/api/card/card_sensitive_query).
  </Step>
</Steps>
